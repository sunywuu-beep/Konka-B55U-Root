# 康佳 B55U 旧电视改造实录：Root ADB 固化、精简预装与踩坑指南

> **实机记录 · 新手向 · 有证据才写成功。** 更新于 2026-10-28。适用于本次测试的康佳 B55U，**不保证其他型号或固件适用**。
>
> 当前进度：**已确认**重启后 Root ADB 自动恢复；**进行中**的是系统精简后的长期稳定性、开机性能和存储空间改善。**首次取得临时 Root 的完整命令尚待补档，因此本仓库目前不是“零基础一键 Root 包”。**

## 1. 为什么做这个项目

这是一台使用多年的康佳 B55U 智能电视。电视本身仍能显示、播放，也能通过 HDMI 使用外部设备，但原有 Android 系统较旧，预装影视平台、推广入口、推送、云服务较多；日常使用希望减少不必要的广告和后台占用。

本项目不是为了刷机、换系统或追求 Root 本身，而是希望：

- **保留现有电视系统与基础硬件功能**：遥控器、画面、声音、电视设置、HDMI 和视频播放正常。
- **获得可持续的本地管理能力**：用 Windows 电脑通过 ADB 检查和管理电视，重启后不再重复临时提权。
- **可回滚地精简**：先停用再验证，记录变化，发现异常立即恢复；不把“看起来像广告”的包一删了之。
- **向后来者展示完整探索过程**：有效步骤、失败日志、错误判断、知识点、验证方法，而不只展示最后几条成功命令。

## 3. 实际取得的成果

1. 找到了这台固件中的 **TVOS 服务侧 Root 命令执行入口**，在测试日志中获得 `uid=0(root) gid=0(root)`。入口的具体调用格式仍须补全，见 [Root 探索与证据](docs/03-root-discovery.md)。
2. 在已取得 Root 的条件下，确认 `/init.rc` 中存在 `flash_recovery` 对 `/system/etc/install-recovery.sh` 的启动调用；备份原文件后安装开机脚本，并恢复 `/system` 为只读。
3. 电视**实际重启后**，Windows 通过 `ADB TCP 5555` 连接，`adb shell id` 返回 `uid=0(root)`；电视开机日志也确认脚本运行。
4. 分两批停用推广和不使用的内容入口。现存记录显示停用数量从 **6 → 10 → 14**。进程快照减少，但 `/data` 空间没有明显改善，**不应宣称显著提速或清出了几百兆空间**。
5. 发现重要的反例：**`com.konka.systemadvert` 停用曾导致遥控器出现异常**，即使名字像广告，也必须保护。注意 10 月 27 日最后的停用清单仍包含它，后续恢复状态需重新以实机确认。

## 4. 新手从哪里开始

**先阅读：[零基础操作路线](docs/02-beginner-route.md)**。不要直接复制网上其他机型的 Root、删包或启动脚本命令。

如果你的电视**已经有 Root ADB**，Windows PowerShell 可以先运行：

```powershell
.\adb.exe connect <电视IP>:5555
.\adb.exe shell id
.\adb.exe shell pm list packages -d
```

`<电视IP>` 替换为电视的局域网地址。第二条如果返回 `uid=0(root)`，说明这个 ADB Shell 当前拥有 Root。它不等于所有 App 自动拥有 Root，也不等于永远不会因刷机丢失。

如果尚未取得 Root：**不要跳过首次提权章节**。本仓库收录确证的探索方向和故障现象，但没有经过保存与再次验证的完整首提权命令，目前不能承诺新手仅靠这些材料就能完成首提权。

## 7. 重要安全原则

- 改动系统前备份相关文件，并准备电视本地输入方式及救援途径；始终先验证回滚。
- 仅在自己拥有或获授权管理的设备上实验。
- **绝不一键删光系统应用**。`com.konka.systemadvert`、`tvos`、`mstar` 电视服务、系统 UI、桌面、输入与遥控相关服务为保护对象。
- Root ADB 监听 `5555` 端口有较高风险。只在可信局域网使用，不设置公网映射；不公开 RSA 私钥、`adb_keys`、设备序列号。
- `/system` 上删除 APK 通常不会自动把空间转移给 `/data`。停用应用不等于卸载软件，也不等于立刻终止常驻进程。
